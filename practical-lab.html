Build Your First
Node.js Server

Step 1

Install Node.js

What to Do

Download Node.js LTS version from nodejs.org. Install it using the Windows installer (.msi file). After installation, open your terminal.

If you see version numbers, the installation is successful. If you get an error, restart your terminal or PC.

Step 5

Write the Server Code

Open app.js and type the following code:

app.js
// Import the built-in http module
const http = require("node:http");

// Create the server
const server = http.createServer((req, res) => {
    // Set response header
    res.writeHead(200, {
        "Content-Type": "text/plain"
    });

    // Send response and end
    res.end("Hello Students! Welcome to Node.js");
});

// Start the server on port 3000
server.listen(3000, () => {
    console.log("Server running at http://localhost:3000");
});

Line 5: createServer() call panni new server object create panrom. Request varum bodhu callback function run aagum.
Line 7: Status code 200 (OK) set panrom, Content-Type header 'text/plain' nu set panrom.
Line 12: Response text anuppi, response-ah end panrom.
Line 16: Server-ah port 3000-la start panrom. Ready aana udan message print aagum.

Step 6

Run the Server

Terminal
node app.js
Expected Terminal Output 
Server running at http://localhost:3000
What this means

Your server is now running! It will keep running until you stop it. The terminal cursor will not return to normal — that's expected because the server is actively listening for requests.

If you see an error

If you see Error: listen EADDRINUSE, port 3000 is already in use. Either close the other program or change the port number in your code (e.g., server.listen(4000, ...)).

Step 8

Add More Endpoints

Stop the server (Ctrl+C), then replace the code in app.js with:

app.js (updated)
const http = require("node:http");

const server = http.createServer((req, res) => {
    // Set JSON content type for all responses
    res.setHeader("Content-Type", "application/json");

    if (req.method === "GET" && req.url === "/") {
        // Home endpoint
        res.writeHead(200);
        res.end(JSON.stringify({
            message: "Welcome to Node.js Server"
        }));

    } else if (req.method === "GET" && req.url === "/about") {
        // About endpoint
        res.writeHead(200);
        res.end(JSON.stringify({
            message: "This is the About page",
            version: "1.0.0"
        }));

    } else if (req.method === "GET" && req.url === "/students") {
        // Students endpoint - returns JSON array
        res.writeHead(200);
        res.end(JSON.stringify([
            { id: 1, name: "Arun", department: "CSE" },
            { id: 2, name: "Priya", department: "ECE" },
            { id: 3, name: "Kumar", department: "IT" }
        ]));

    } else if (req.method === "GET" && req.url === "/contact") {
        // Contact endpoint
        res.writeHead(200);
        res.end(JSON.stringify({
            email: "trainer@college.edu",
            department: "Computer Science"
        }));

    } else {
        // 404 - Not Found
        res.writeHead(404);
        res.end(JSON.stringify({
            error: "Endpoint not found",
            availableEndpoints: ["/", "/about", "/students", "/contact"]
        }));
    }
});

server.listen(3000, () => {
    console.log("Server running on http://localhost:3000");
    console.log("Available endpoints: /, /about, /students, /contact");
});

Step 9

Handle Invalid Endpoints

Already Done!

In Step 8, the else block already handles unknown routes by returning a 404 JSON response. This tells the client "this endpoint doesn't exist" along with a list of available endpoints.

Tanglish

"User /xyz maari unknown URL visit pannina, namma else block run aagi 404 error JSON return pannum. Available endpoints list-um kuduppom — user-ku helpful-ah irukkum."

Try visiting http://localhost:3000/doesnotexist to verify the 404 response works.

Step 10

Add npm Scripts

Open package.json and update the "scripts" section:

package.json (scripts section)
{
  "scripts": {
    "start": "node app.js",
    "dev": "node --watch app.js"
  }
}

Now you can run your server using:

Terminal
# Production start
npm start

# Development mode (auto-restart on file changes, Node 18.11+)
npm run dev
Tanglish

"npm start run pannina node app.js automatically run aagum. npm run dev run pannina --watch flag use aagi file change pannum bodhu auto-restart aagum (Node.js 18.11+ irundhaa). Ivlo dhaan — ipo neenga npm scripts use panna theriyum!"

Note on --watch

The --watch flag is available in Node.js 18.11 and later versions. If your Node.js version is older, you can use nodemon (a third-party package) instead: npm install --save-dev nodemon and set dev script to "nodemon app.js".

Step 12

Student Practical Assessment

Part A: Short Answer Questions (5 marks)

  1. What is Node.js and what engine does it use?
    Node.js is a JavaScript runtime environment built on Google Chrome's V8 engine. It allows you to run JavaScript outside the browser.
  2. What does require("node:http") do?
    It imports the built-in HTTP module that allows you to create HTTP servers and handle requests.
  3. What is the purpose of res.end()?
    It sends the response body to the client and signals that the response is complete. No more data can be written after calling res.end().
  4. What does port 3000 mean in server.listen(3000)?
    Port 3000 is the network port number where the server listens for incoming connections. It's like a door number — the browser connects to the server through this specific port.
  5. What is the difference between res.writeHead() and res.setHeader()?
    res.setHeader() sets a single header. res.writeHead() sets the status code and optionally multiple headers at once. writeHead() must be called before sending the body.

Build a "Student Information Server" with the following requirements:

  • Create endpoints: /, /students, /departments, /info
  • The /students endpoint should return at least 5 students with id, name, department, and year fields
  • The /departments endpoint should return a list of departments
  • The /info endpoint should return college name and address
  • Handle 404 errors properly
  • Use JSON for all responses
  • Add a "start" script in package.json
